11  Part 2 — Hadoop MapReduce

11.1 Learning Objectives

By the end of this part, you will be able to:

  1. Explain how Hadoop MapReduce differs from Python MapReduce.
  2. Understand the Hadoop Distributed File System (HDFS).
  3. Install and configure Hadoop in pseudo-distributed mode.
  4. Start and stop Hadoop services.
  5. Upload files to HDFS.
  6. Run a real Hadoop MapReduce program.
  7. Execute MapReduce jobs on datasets of increasing size.
  8. Inspect mapper, reducer, and job-level results.
  9. Compare local Python execution with Hadoop execution.
  10. Understand why Hadoop becomes useful when datasets are too large for a single machine.

12 From Python MapReduce to Hadoop

In Part 1, we implemented the MapReduce idea ourselves using Python.

The basic workflow was:

Input Dataset
     |
     v
   Mapper
     |
     v
Key-Value Pairs
     |
     v
  Shuffle
     |
     v
Grouped Key-Value Pairs
     |
     v
  Reducer
     |
     v
   Output

Hadoop implements the same fundamental idea, but provides the infrastructure required to distribute processing across machines.

The Hadoop workflow can be viewed as:

                 Hadoop Cluster
-------------------------------------------------
                 HDFS
                  |
                  v
              Input Data
                  |
                  v
              Map Tasks
                  |
                  v
        Shuffle and Sort
                  |
                  v
            Reduce Tasks
                  |
                  v
              HDFS Output
-------------------------------------------------

The important difference is that Hadoop manages many of the distributed-system tasks for us.

For example, Hadoop can handle:

  • distributing input data,
  • starting mapper tasks,
  • transferring intermediate data,
  • sorting intermediate keys,
  • starting reducer tasks,
  • monitoring tasks,
  • handling task failures,
  • storing output in HDFS.

13 Hadoop Components

For this practical, we will mainly work with:

13.0.1 Hadoop Distributed File System — HDFS

HDFS is the storage layer.

Local Computer
     |
     | put
     v
    HDFS
     |
     +---- file 1
     +---- file 2
     +---- file 3

13.0.2 Hadoop MapReduce

MapReduce is the processing layer.

HDFS Input
    |
    v
Mapper
    |
    v
Shuffle + Sort
    |
    v
Reducer
    |
    v
HDFS Output

13.0.3 YARN

YARN manages computing resources and schedules applications in a Hadoop cluster.

For this practical, we will use Hadoop in pseudo-distributed mode.

This means Hadoop runs on a single computer, but Hadoop components behave approximately as they would in a distributed environment.

14 Important Hadoop Services

A simplified Hadoop installation contains several important services.

Service Purpose
NameNode Manages HDFS metadata
DataNode Stores HDFS data blocks
ResourceManager Manages cluster resources
NodeManager Manages computation on a node
Secondary NameNode Performs checkpoint-related work

For this practical:

NameNode
    |
    +---- HDFS metadata

DataNode
    |
    +---- Actual HDFS data

ResourceManager
    |
    +---- Resource scheduling

NodeManager
    |
    +---- Executes tasks

chmod 600 ~/.ssh/authorized_keys

yes

23 Configure core-site.xml

Open:

nano $HADOOP_HOME/etc/hadoop/core-site.xml

Replace the contents with:

<configuration>

    <property>
        <name>fs.defaultFS</name>
        <value>hdfs://localhost:9000</value>
    </property>

</configuration>

24 Configure hdfs-site.xml

Create directories:

mkdir -p ~/hadoop_data/hdfs/namenode
mkdir -p ~/hadoop_data/hdfs/datanode

Open:

nano $HADOOP_HOME/etc/hadoop/hdfs-site.xml

Use:

<configuration>

    <property>
        <name>dfs.replication</name>
        <value>1</value>
    </property>

    <property>
        <name>dfs.namenode.name.dir</name>
        <value>file:///home/hadoop/hadoop_data/hdfs/namenode</value>
    </property>

    <property>
        <name>dfs.datanode.data.dir</name>
        <value>file:///home/hadoop/hadoop_data/hdfs/datanode</value>
    </property>

</configuration>

Important: Replace /home/hadoop/ with your actual home directory if you used a different username.

25 Configure MapReduce

Open:

nano $HADOOP_HOME/etc/hadoop/mapred-site.xml

Use:

<configuration>

    <property>
        <name>mapreduce.framework.name</name>
        <value>yarn</value>
    </property>

</configuration>

26 Configure YARN

Open:

nano $HADOOP_HOME/etc/hadoop/yarn-site.xml

Use:

<configuration>

    <property>
        <name>yarn.nodemanager.aux-services</name>
        <value>mapreduce_shuffle</value>
    </property>

</configuration>

38 Understanding the Hadoop Word Count Program

In Part 1 we manually implemented:

Mapper
   ↓
Shuffle
   ↓
Reducer

Hadoop performs the shuffle and sorting stage automatically.

Conceptually, our mapper produces:

Hadoop       1
is           1
a            1
distributed  1
system       1
Hadoop       1
...

Hadoop then groups identical keys:

Hadoop       [1, 1, 1]
distributed  [1, 1]
MapReduce    [1, 1]
...

The reducer calculates:

Hadoop       3
distributed  2
MapReduce    2
...

39 Create the Hadoop Streaming Mapper

We will use Hadoop Streaming because it allows us to write mapper and reducer programs in Python.

Create:

nano mapper.py

Use:

#!/usr/bin/env python3

import sys

for line in sys.stdin:
    words = line.strip().split()

    for word in words:
        word = word.lower()
        print(f"{word}\t1")

40 Create the Hadoop Streaming Reducer

Create:

nano reducer.py

Use:

#!/usr/bin/env python3

import sys

current_word = None
current_count = 0

for line in sys.stdin:

    line = line.strip()

    word, count = line.split("\t", 1)

    count = int(count)

    if current_word == word:
        current_count += count

    else:

        if current_word is not None:
            print(f"{current_word}\t{current_count}")

        current_word = word
        current_count = count

if current_word is not None:
    print(f"{current_word}\t{current_count}")

41 Make the Programs Executable

Run:

chmod +x mapper.py
chmod +x reducer.py

Check:

  |

  |
  v

44 Run MapReduce Using Hadoop

First remove any previous output directory:

hdfs dfs -rm -r /user/$USER/output

If it does not exist, that is fine.

Run Hadoop Streaming:

hadoop jar $HADOOP_HOME/share/hadoop/tools/lib/hadoop-streaming-*.jar \
-input /user/$USER/input \
-output /user/$USER/output \
-mapper mapper.py \
-reducer reducer.py

Hadoop will now execute the MapReduce job.

45 Understand the Job Output

After the job finishes:

hdfs dfs -ls /user/$USER/output

You should see files similar to:

_SUCCESS
part-00000

The _SUCCESS file indicates successful job completion.

The part-00000 file contains the reducer output.

Display it:

hdfs dfs -cat /user/$USER/output/part-00000

63 Understand the Hadoop Execution Flow

The complete process is approximately:

                 HDFS
                  |
                  v
             Input Splits
                  |
          +-------+-------+
          |               |
          v               v
       Mapper          Mapper
          |               |
          v               v
      Intermediate    Intermediate
       key-values      key-values
          |               |
          +-------+-------+
                  |
                  v
            Shuffle/Sort
                  |
          +-------+-------+
          |               |
          v               v
       Reducer          Reducer
          |               |
          +-------+-------+
                  |
                  v
                HDFS
                Output

On a real multi-node cluster, these tasks can execute across different machines.

In our pseudo-distributed setup, they execute on the same computer.

64 Why Use Hadoop?

Suppose we have:

Dataset = 500 MB

A normal Python program may be perfectly adequate.

But imagine:

Dataset = 500 GB

or:

Dataset = 5 TB

A single computer may not have enough memory or processing capacity.

A Hadoop cluster can distribute the work.

For example:

             5 TB Dataset
                  |
        +---------+---------+

65 Data Locality

One of Hadoop’s important ideas is data locality.

Instead of always moving data to the computation:

Data
  |
  | transfer
  v
Computation

Hadoop tries to move computation closer to the data.

Conceptually:

        Data
         |
         v
      Node 1
         |
      Mapper

This reduces unnecessary network transfer in distributed environments.

66 HDFS Blocks

HDFS divides large files into blocks.

For example, conceptually:

Large File
--------------------------------
| Block 1 | Block 2 | Block 3 |
--------------------------------

These blocks can be distributed across DataNodes.

In a real cluster:

NameNode
    |
    +---- Block 1 -> DataNode 1
    |
    +---- Block 2 -> DataNode 2
    |
    +---- Block 3 -> DataNode 3

67 Replication

HDFS normally maintains multiple copies of blocks.

For example:

Block A

DataNode 1 ---- copy
DataNode 2 ---- copy
DataNode 3 ---- copy

If one machine fails, another copy may still be available.

For our single-machine practical, we configured:

<property>
    <name>dfs.replication</name>
    <value>1</value>
</property>

because there is only one DataNode.

70 Revenue Mapper

Use:

#!/usr/bin/env python3

import sys
import csv

reader = csv.reader(sys.stdin)

header = next(reader, None)

for row in reader:

    try:

        if len(row) < 8:
            continue

        quantity = float(row[3])
        unit_price = float(row[5])
        country = row[7]

        if not country:
            continue

        revenue = quantity * unit_price

        print(f"{country}\t{revenue}")

    except (ValueError, IndexError):
        continue

74 An Important Observation

Hadoop itself introduces overhead.

For a tiny dataset:

Python:
Input → Processing → Output

may be faster.

Hadoop has additional operations:

Input
  ↓
HDFS
  ↓
Job submission
  ↓
Task initialization
  ↓
Mapper
  ↓
Shuffle
  ↓
Reducer
  ↓
HDFS
  ↓
Output

Therefore:

Hadoop is not automatically faster for every dataset.

Its major advantage is the ability to process very large datasets across multiple machines.

77 Troubleshooting

77.1 Problem: hadoop: command not found

Check:

echo $HADOOP_HOME

Then:

echo $PATH

Make sure Hadoop’s bin and sbin directories are in PATH.

77.2 Problem: Java not found

Run:

java -version

Then:

echo $JAVA_HOME

Make sure JAVA_HOME points to the Java installation.

77.3 Problem: NameNode is not running

Run:

jps

If NameNode is missing, check the Hadoop logs.

Also check:

hdfs dfsadmin -report

77.4 Problem: DataNode is not running

Run:

jps

Check the DataNode logs under the Hadoop log directory.

77.5 Problem: Output directory already exists

Hadoop normally refuses to write to an existing output directory.

Remove it:

hdfs dfs -rm -r /user/$USER/output

Then run the job again.

77.6 Problem: Permission denied

Check the permissions of:

~/.ssh
~/.ssh/authorized_keys

Use:

chmod 700 ~/.ssh
chmod 600 ~/.ssh/authorized_keys
